# レポート出力システム 仕様書（研修用サンプルコード）

## 1. システム概要

本システムは、SOLID原則を学ぶ研修用のサンプルアプリケーションです。
業務で頻出する典型的な処理フローである「売上データを取得 → フォーマット(CSV/JSON/Markdown)に整形 → 出力先(コンソール/ファイル/メール)に届ける」という一連の処理を実装します。
同一の機能要件に対し、意図的に原則に違反した「Badパターン」と、SOLID原則を適用した「Goodパターン」の2つの実装を用意し、設計の違いを比較できるようにします。

## 2. 開発環境・前提条件

* **言語およびフレームワーク:** C# (.NET 10) を使用します。
* **アプリケーション形態:** コンソールアプリケーションとして実装します。
* **依存関係（Good版のみ）:** 依存性の注入（DI）を行うため、`Microsoft.Extensions.DependencyInjection`パッケージを利用します。

## 3. 機能要件

システムのコアとなる機能は以下の3ステップです。

* **データ取得:** * 商品名（Product）と売上金額（Amount）を持つ売上レコードのリストを取得します。
  * ※研修用のため、実際のデータベース接続は行わず、インメモリのダミーデータ（Apple: 100, Banana: 200, Cherry: 300）を使用します。

* **データ整形 (フォーマット):** * 取得したデータを以下の3種類の形式のいずれかに変換します。
  * **CSV:** ヘッダ（Product,Amount）付きのカンマ区切り文字列。
  * **JSON:** オブジェクトの配列形式。`System.Text.Json`を用いて整形します。
  * **Markdown:** 表形式（テーブル）の文字列。

* **データ出力:** * 整形された文字列データを以下の3種類のいずれかの方法で出力・送信します。
  * **Console:** 標準出力（コンソール）へ出力します。
  * **File:** 指定されたファイルパス（例: `report.json`）にテキストファイルとして書き出します。
  * **Email:** 指定された宛先（例: `boss@example.com`）へメールとして送信します。
    * ※研修用のため、実際のSMTP送信は行わず、コンソールへの擬似的なログ出力で代用します。

## 4. 設計要件：Badパターン

SOLIDの全原則に違反するアンチパターンとして実装します。

| 違反原則 | 実装すべき仕様（アンチパターンの再現） |
| --- | --- |
| **SRP** (単一責任) | 1つのGodクラス（`ReportManager`）の中に、ダミーデータ生成、整形、出力の全ロジックを詰め込みます。 |
| **OCP** (開放閉鎖) | フォーマットや出力先の分岐をすべて `if / else if` でハードコードし、機能追加時に既存コードの改修を必須にします。 |
| **LSP** (リスコフ置換) | 「PDF形式の場合はコンソール出力不可」という制約を設け、例外 (`NotSupportedException`) をスローさせることで親の契約を破る伏線を作ります。 |
| **ISP** (インターフェース分離) | ※本Badコード内ではクラス単体のアンチパターンを強調するため、明示的な巨大インターフェースは設けず、すべて直接実装します。 |
| **DIP** (依存関係逆転) | 接続文字列やSMTPサーバーなどの設定値をクラス内にハードコードし、具象に直接依存させます。 |

---

## 5. 設計要件：Goodパターン

SOLIDの5原則をすべて遵守したクリーンなアーキテクチャとして実装します。

* **ドメイン層（Domain）:**
  * 売上データを表す `SalesRecord` を単一の責務（データ保持）を持つ `record` 型として定義します。

* **データアクセス層（DataAccess）:**
  * 抽象である `ISalesRepository` インターフェースを定義し、「売上を取得する」最小限のメソッドのみを持たせます（ISP・DIP）。
  * 具象としてダミーデータを返す `InMemorySalesRepository` を実装します（SRP）。

* **フォーマット層（Formatters）:**
  * 拡張ポイントとして `IReportFormatter` インターフェースを用意します（OCP）。
  * このインターフェースには識別子（FormatName）と整形処理（Format）を持たせます。
  * 具象クラスとして `CsvFormatter`、`JsonFormatter`、`MarkdownFormatter` を個別に実装し、例外を投げず必ず文字列を返す契約を守らせます（SRP・LSP）。

* **出力層（Output）:**
  * 責務単位でインターフェースを小さく分割します（`IFileWriter`, `IEmailSender`, `IConsoleWriter`）（ISP）。
  * それぞれのインターフェースに対応する具象クラス（`FileWriter`, `SmtpEmailSender`, `ConsoleWriter`）を実装します（SRP）。

* **サービス層（Services）:**
  * 上記の各層を連携させる調整役として `ReportService` を実装します（SRP）。
  * コンストラクタ経由ですべての依存（インターフェース）を受け取り、内部で直接具象クラスを `new` しないようにします（DIP）。

* **エントリーポイント（Program.cs / Composition Root）:**
  * アプリケーションの起動地点でのみDIコンテナ (`ServiceCollection`) を用いて具象クラスの組み立てを行います。
  * 新しいフォーマットを追加する際は、このファイルのDI登録を1行追加するだけで済む構造とします（OCP）。
