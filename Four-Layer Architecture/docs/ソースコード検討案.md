# 4層アーキテクチャの研修資料用 Todo サンプル

このディレクトリには、以下の実装を含む実行可能な .NET 10 Minimal API サンプルがあります。

```text
TodoApp.Presentation  → TodoApp.Application → TodoApp.Domain ← TodoApp.Infrastructure
                                      ↑
                         Domain/Application の単体テスト
```

## 実行・テスト

リポジトリルートから次を実行します。

```bash
dotnet run --project "Four-Layer Architecture/TodoApp.Presentation"
dotnet test "Four-Layer Architecture/TodoApp.Domain.Tests"
dotnet test "Four-Layer Architecture/TodoApp.Application.Tests"
```

ブラウザーで `http://localhost:5000/` を開くと、APIが起動していることと利用可能な
エンドポイントの一覧をJSONで確認できます。このサンプルは画面を持たないMinimal APIのため、
ブラウザーにTodo一覧の画面は表示されません。Todoの操作は `/api/todos` にHTTPリクエストを
送信してください。

`/api/todos` で一覧、取得、作成、更新、完了、削除を行えます。入力不備は構造化された
`400 ValidationProblem`、存在しない ID は `404`、重複タイトルと完了済みタスクの再完了は
`409` を返します。予期しない例外はサーバーログに詳細を記録し、クライアントには固定文言
（`予期しないエラーが発生しました。`）だけを返します。

## APIを初めて使う人向けの操作例

以下はPowerShellで実行する例です。先にAPIを起動し、`$baseUrl` は実際に表示された
待ち受けURLに合わせてください。作成時に返された `id` を、更新・完了・削除で使用します。

```powershell
$baseUrl = "http://localhost:5000"

# 1. 作成: POST でタイトルと説明を送る
$todo = Invoke-RestMethod `
    -Method Post `
    -Uri "$baseUrl/api/todos" `
    -ContentType "application/json" `
    -Body '{"title":"研修資料を読む","description":"4層アーキテクチャを確認する"}'

$todo
$id = $todo.id
```

作成が成功すると `201 Created` が返り、レスポンスにタスクの `id`、タイトル、説明、
完了状態（`isCompleted: false`）が含まれます。

```powershell
# 2. 更新: PUT で同じIDを指定し、タイトルや説明を置き換える
Invoke-RestMethod `
    -Method Put `
    -Uri "$baseUrl/api/todos/$id" `
    -ContentType "application/json" `
    -Body '{"title":"研修資料を復習する","description":"コード例も実行する"}'

# 3. 完了: POST を完了用URLへ送る（本文は不要）
Invoke-WebRequest `
    -Method Post `
    -Uri "$baseUrl/api/todos/$id/complete"

# 4. 削除: DELETE を同じIDへ送る
Invoke-WebRequest `
    -Method Delete `
    -Uri "$baseUrl/api/todos/$id"
```

更新・完了・削除が成功すると `204 No Content` が返ります。現在の一覧を確認する場合は
`Invoke-RestMethod -Uri "$baseUrl/api/todos"` を実行します。タイトルが空、または100文字を
超える場合は `400`、存在しないIDは `404`、同じタイトルの作成や完了済みタスクの再完了は
`409` です。削除後に同じIDを取得すると `404` になります。

## 研修用の簡略化と SQL 化する際の復元

現在の Infrastructure は外部サービスなしで実行できるよう `ConcurrentDictionary` の
インメモリ実装です。再起動でデータが消えること、認証・ページング・監査ログを扱わないことは
研修用の意図的な簡略化です。Application は Domain エンティティを DTO に変換し、HTTP 層へ
エンティティを漏らしません。

実 DB に置き換える場合は、Infrastructure に `TodoRow`（`Id`, `Title`, `Description`,
`IsCompleted`, `CreatedAt`, `UpdatedAt`）を SQL の行/EF Core エンティティとして追加し、
`TodoRowMapper.ToDomain` と `ToRow` を設けます。復元時は Domain の復元用ファクトリ
（または ORM の materialization 用コンストラクター）で不変条件を通し、保存時は
`TodoItem` の状態を行へ写像します。`ITodoRepository` は変更しないため、Application と
Presentation は DB 技術に依存しません。移行時にだけ EF Core provider と migration を追加します。

## Part 1: 全体構成と共通基盤

### プロジェクト構成イメージ
```
TodoApp/
```

### 依存関係の方向（重要）
```
Presentation → Application → Domain ← Infrastructure
```
- 上位層が下位層に依存します。
- **Domain層は何にも依存しない**のがポイントです（最も内側）。

## Part 2: Domain層の本体

### Todoエンティティ

```csharp
// ==========================================
// TodoApp.Domain / Todos / TodoItem.cs
// Todoエンティティ（業務ルールを持つ）
// ==========================================
using TodoApp.Domain.Common;

namespace TodoApp.Domain.Todos;

public class TodoItem : EntityBase
{
    public string Title { get; private set; }
    public string? Description { get; private set; }
    public bool IsCompleted { get; private set; }

    // コンストラクタで不変条件（業務ルール）を保証
    public TodoItem(string title, string? description = null)
    {
        ValidateTitle(title);
        Title = title;
        Description = description;
        IsCompleted = false;
    }

    // --- 業務ロジックはエンティティ内に集約 ---

    public void ChangeTitle(string newTitle)
    {
        ValidateTitle(newTitle);
        Title = newTitle;
        MarkUpdated(); // 基底クラスの共通処理を再利用
    }

    public void ChangeDescription(string? newDescription)
    {
        Description = newDescription;
        MarkUpdated();
    }

    public void Complete()
    {
        if (IsCompleted)
            throw new InvalidOperationException("このタスクは既に完了しています。");

        IsCompleted = true;
        MarkUpdated();
    }

    public void Reopen()
    {
        if (!IsCompleted)
            throw new InvalidOperationException("このタスクはまだ完了していません。");

        IsCompleted = false;
        MarkUpdated();
    }

    // --- バリデーションを共通化 ---
    private static void ValidateTitle(string title)
    {
        if (string.IsNullOrWhiteSpace(title))
            throw new ArgumentException("タイトルは必須です。", nameof(title));

        if (title.Length > 100)
            throw new ArgumentException("タイトルは100文字以内で入力してください。", nameof(title));
    }
}
```

### アプリケーションサービス（ユースケース）

```csharp
// ==========================================
// TodoApp.Application / Todos / ITodoService.cs
// ==========================================
using TodoApp.Application.Todos.Dtos;

namespace TodoApp.Application.Todos;

public interface ITodoService
{
    Task<TodoDto> CreateAsync(CreateTodoRequest request);
    Task<TodoDto?> GetAsync(Guid id);
    Task<IReadOnlyList<TodoDto>> GetAllAsync();
    Task UpdateAsync(Guid id, UpdateTodoRequest request);
    Task CompleteAsync(Guid id);
    Task DeleteAsync(Guid id);
}
```

```csharp
// ==========================================
// TodoApp.Application / Todos / TodoService.cs
// ユースケースの調整役（業務ルールはDomainに委譲）
// ==========================================
using TodoApp.Application.Todos.Dtos;
using TodoApp.Domain.Todos;

namespace TodoApp.Application.Todos;

public class TodoService : ITodoService
{
    private readonly ITodoRepository _repository;

    // 依存はインターフェース経由（インフラの実装を知らない）
    public TodoService(ITodoRepository repository)
    {
        _repository = repository;
    }

    public async Task<TodoDto> CreateAsync(CreateTodoRequest request)
    {
        var todo = new TodoItem(request.Title, request.Description);
        await _repository.AddAsync(todo);
        return TodoMapper.ToDto(todo);
    }

    public async Task<TodoDto?> GetAsync(Guid id)
    {
        var todo = await _repository.GetByIdAsync(id);
        return todo is null ? null : TodoMapper.ToDto(todo);
    }

    public async Task<IReadOnlyList<TodoDto>> GetAllAsync()
    {
        var items = await _repository.GetAllAsync();
        return items.Select(TodoMapper.ToDto).ToList();
    }

    public async Task UpdateAsync(Guid id, UpdateTodoRequest request)
    {
        var todo = await GetOrThrowAsync(id);
        todo.ChangeTitle(request.Title);
        todo.ChangeDescription(request.Description);
        await _repository.UpdateAsync(todo);
    }

    public async Task CompleteAsync(Guid id)
    {
        var todo = await GetOrThrowAsync(id);
        todo.Complete(); // 業務ルールはDomainが判断
        await _repository.UpdateAsync(todo);
    }

    public async Task DeleteAsync(Guid id)
    {
        await _repository.DeleteAsync(id);
    }

    // 「存在チェック＋取得」を共通化
    private async Task<TodoItem> GetOrThrowAsync(Guid id)
    {
        var todo = await _repository.GetByIdAsync(id);
        return todo
            ?? throw new KeyNotFoundException($"指定されたタスクが見つかりません: {id}");
    }
}
```

---

### ポイント（資料での解説用）
- **業務判断はしない**：完了可否の判定などは `todo.Complete()` に委譲。
- **DTOで層を分離**：エンティティを直接外に出さない。

## Part 4: Infrastructure層

### 汎用リポジトリの基底実装

```csharp
// ==========================================
// TodoApp.Infrastructure / Persistence / InMemoryRepositoryBase.cs
// 全リポジトリ共通のCRUDをインメモリで実装
// ==========================================
using System.Collections.Concurrent;
using TodoApp.Domain.Common;

namespace TodoApp.Infrastructure.Persistence;

public abstract class InMemoryRepositoryBase<T> : IRepository<T>
    where T : EntityBase
{
    // スレッドセーフな簡易ストア
    protected readonly ConcurrentDictionary<Guid, T> Store = new();

    public Task<T?> GetByIdAsync(Guid id)
    {
        Store.TryGetValue(id, out var entity);
        return Task.FromResult(entity);
    }

    public Task<IReadOnlyList<T>> GetAllAsync()
    {
        IReadOnlyList<T> list = Store.Values.ToList();
        return Task.FromResult(list);
    }

    public Task AddAsync(T entity)
    {
        Store[entity.Id] = entity;
        return Task.CompletedTask;
    }

    public Task UpdateAsync(T entity)
    {
        Store[entity.Id] = entity;
        return Task.CompletedTask;
    }

    public Task DeleteAsync(Guid id)
    {
        Store.TryRemove(id, out _);
        return Task.CompletedTask;
    }
}
```

### Todo専用リポジトリの実装

```csharp
// ==========================================
// TodoApp.Infrastructure / Persistence / InMemoryTodoRepository.cs
// 基底実装を継承し、固有処理だけ追加
// ==========================================
using TodoApp.Domain.Todos;

namespace TodoApp.Infrastructure.Persistence;

public class InMemoryTodoRepository
    : InMemoryRepositoryBase<TodoItem>, ITodoRepository
{
    // 共通CRUDは基底クラスに任せ、固有処理のみ実装
    public Task<IReadOnlyList<TodoItem>> GetIncompleteAsync()
    {
        IReadOnlyList<TodoItem> list =
            Store.Values.Where(t => !t.IsCompleted).ToList();
        return Task.FromResult(list);
    }
}
```

### API エンドポイント定義（ルーティングを集約）

```csharp
// ==========================================
// TodoApp.Presentation / Endpoints / TodoEndpoints.cs
// Todo関連のエンドポイントを1か所にまとめる
// ==========================================
using TodoApp.Application.Todos;
using TodoApp.Application.Todos.Dtos;

namespace TodoApp.Presentation.Endpoints;

public static class TodoEndpoints
{
    public static void MapTodoEndpoints(this WebApplication app)
    {
        var group = app.MapGroup("/api/todos").WithTags("Todos");

        group.MapGet("/", async (ITodoService service) =>
            Results.Ok(await service.GetAllAsync()));

        group.MapGet("/{id:guid}", async (Guid id, ITodoService service) =>
        {
            var todo = await service.GetAsync(id);
            return todo is null ? Results.NotFound() : Results.Ok(todo);
        });

        group.MapPost("/", async (CreateTodoRequest req, ITodoService service) =>
        {
            var created = await service.CreateAsync(req);
            return Results.Created($"/api/todos/{created.Id}", created);
        });

        group.MapPut("/{id:guid}", async (
            Guid id, UpdateTodoRequest req, ITodoService service) =>
        {
            await service.UpdateAsync(id, req);
            return Results.NoContent();
        });

        group.MapPost("/{id:guid}/complete", async (
            Guid id, ITodoService service) =>
        {
            await service.CompleteAsync(id);
            return Results.NoContent();
        });

        group.MapDelete("/{id:guid}", async (Guid id, ITodoService service) =>
        {
            await service.DeleteAsync(id);
            return Results.NoContent();
        });
    }
}
```

### 例外を横断的に処理（各所でtry-catchしない）

```csharp
// ==========================================
// TodoApp.Presentation / Middleware / ExceptionHandlingMiddleware.cs
// 業務例外をHTTPレスポンスに変換する共通処理
// ==========================================
using System.Net;

namespace TodoApp.Presentation.Middleware;

public class ExceptionHandlingMiddleware
{
    private readonly RequestDelegate _next;

    public ExceptionHandlingMiddleware(RequestDelegate next) => _next = next;

    public async Task InvokeAsync(HttpContext context)
    {
        try
        {
            await _next(context);
        }
        catch (Exception ex)
        {
            // 例外の種類に応じてステータスコードを決定
            var statusCode = ex switch
            {
                KeyNotFoundException      => HttpStatusCode.NotFound,
                ArgumentException         => HttpStatusCode.BadRequest,
                InvalidOperationException => HttpStatusCode.Conflict,
                _                         => HttpStatusCode.InternalServerError
            };

            context.Response.StatusCode = (int)statusCode;
            await context.Response.WriteAsJsonAsync(new { error = ex.Message });
        }
    }
}
```

```csharp
// ==========================================
// TodoApp.Presentation / Program.cs

using TodoApp.Application;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddApplication();
builder.Services.AddInfrastructure();

// Swagger（動作確認用）
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

var app = builder.Build();

if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();
}

// 共通例外ハンドリング
app.UseMiddleware<ExceptionHandlingMiddleware>();

// エンドポイントの登録
app.MapTodoEndpoints();

app.Run();
```

- **Presentationは薄く**：受け取って `ITodoService` に渡すだけ。
- **例外処理を横断化**：各エンドポイントで `try-catch` を書かない。

## 全体まとめ（資料の締めに）

| 層 | 役割 | 今回の主なファイル |
|---|---|---|
| Presentation | 外部との入出力 | `TodoEndpoints`, `Program.cs` |
| Application | ユースケースの調整 | `TodoService`, `TodoDto` |
| Domain | 業務ルール | `TodoItem`, `ITodoRepository` |
| Infrastructure | 技術的詳細 | `InMemoryTodoRepository` |

**依存の方向**：`Presentation → Application → Domain ← Infrastructure`
→ Domainが中心にあり、技術に依存しないのが4層アーキテクチャの肝です。
